# ADR-011: persisted document timeline

Date: 7 October 2026. Optional scope authorized by user continuation of the recommended linked transaction timeline. Requirement support: UI-01, AUTH-01/02, ARCH-01/02, DB-01, PO-01, SO-01, REPORT-01, TEST-01/02/03. No official workflow/status or trainer decision changes.

Details of PO, SO and stock operations link to `/timeline?kind=PO|SO|Operation&id=...`. Native controller delegates to DocumentTimelineService and DocumentTimelineRepositoryInterface with prepared MySQL implementation/manual constructor injection. Service validates document visibility before querying events/links. Admin/WarehouseStaff may read these document families; Sales reads own SO only and receives no related operation link or return-operation event. Existing detail/action guards remain authoritative.

Timeline projects immutable creation metadata, stored SO approval metadata, operation posting metadata, relevant successful audit actions and signed ledger movements. Optional operation proposal audit is excluded because creation/header reason already represents it. Receipt/issue/post audit actions are excluded in favor of their actual ledger evidence; SO approval audit is excluded in favor of stored approval actor/time. Review/cancel/close/reject reasons come from recorded audit metadata, never the current overwritten operation decision_reason. Current SO/PO status is not treated as status at creation. Missing historical events remain missing; no retroactive audit writes or inferred transitions.

Each ledger event identifies original ledger ID, product SKU, warehouse and signed change. Posted supplier/customer returns are linked to the original PO/SO via source_ledger_id with EXISTS to avoid duplicate events for multi-item returns. Return operation timeline links back to original PO/SO documents. Actor/product/warehouse display names reflect current master records, not historical name snapshots. Only reason/decision are exposed from audit JSON; no IP, user-agent, arbitrary metadata or failure/blocked events.

Latest recorded events first; deterministic timestamp/sequence/title order and maximum 100 events with an explicit truncation notice. Admin can consult Audit Trail for older audit history; source ledger remains intact. This is a bounded document view rather than an exhaustive paginated ledger archive. No schema, transaction, stock or audit-write changes. Physical-device results and trainer decisions remain separately pending. Evidence: docs/testing/timeline-2026-10-07.md.
