# Refactor Log

Date: 2026-08-31 (R-001 to R-005); updated 2026-10-07 (R-006 to R-013)
Scope: Phases 0-7 implementation evidence and later hardening

| Entry | Smell / Pressure | Technique | Before | After | Verification |
|---|---|---|---|---|---|
| R-001 | Authentication checks risked becoming ad hoc in controllers. | Extracted authorization/session boundary. | Controllers would need to inspect raw session state and roles directly. | `AuthGuard`, `AuthContext`, `Authorization`, and `SessionManager` centralize server-side auth decisions. | `AuthorizationTest`, `SessionManagerTest`, `AuthServiceTest`, and full `composer test`. |
| R-002 | MySQL persistence would make service tests slow and brittle. | Introduced repository interfaces and in-memory repositories. | Services would have been coupled directly to PDO repositories. | Services depend on `*RepositoryInterface`; `MySql*` repositories serve runtime and `InMemory*` repositories serve unit tests. | Repository/service unit tests plus MySQL integration tests. |
| R-003 | Receipt and issue workflows duplicated stock mutation rules and rollback risk. | Extracted transaction orchestration to `StockService`. | PO receipt and SO issue could each update stock and ledger independently. | `PurchaseOrderService` and `SalesOrderService` call `StockService::receive()` / `issue()` with source-state callbacks. | `StockServiceReceiptTest`, `StockServiceIssueTest`, `PurchaseOrderReceiptIntegrationTest`, `SalesOrderIssueIntegrationTest`. |
| R-004 | CSV response and formula escaping could spread across report controllers. | Extracted response/formatting helper. | Report endpoints would build headers and rows manually. | `CsvResponse` and `ReportService` own CSV generation and formula neutralization. | `ReportServiceTest` and HTTP report smoke test. |
| R-005 | Error responses and validation failures were inconsistent across browser/API paths. | Added explicit error responder and shared validation helpers. | Front controller returned mixed raw exception output and services used repeated small checks. | `ErrorResponder`, `ValidationException`, and `InputValidator` provide consistent status/message behavior while preserving existing service rules. | `ErrorResponseTest`, `ValidationTest`, `SecurityAuditTest`, full `composer test`, `composer analyse`. |
| R-006 | Order status was validated outside the stock transaction: two requests that both read Approved could issue the same SO twice, and CSV batches could import partially. | Move the source-order lock and state check inside the transaction owned by `StockService`; route batch imports through a transaction interface. | Stock rows were locked, but order state was read before the transaction; import rows committed one by one. | Workflow services lock the order inside `StockService::transaction`, then lock stock in sorted order; nested operations join the owned transaction. `CsvImportService` uses `TransactionManagerInterface` / `MySqlTransactionManager` (ADR-004, ADR-006). | `AuditRemediationIntegrationTest`, `ParallelStockIntegrationTest::testTwoProcessesIssueSameOrderOnlyOnce`. |
| R-007 | Double clicks or network retries could repeat a receipt or issue. | Extracted idempotency into its own service and repository. | Each workflow would need its own duplicate check. | `OperationIdempotency` + `OperationRequestRepositoryInterface` used by PO receipt and SO issue (ADR-008). | `OperationIdempotencyIntegrationTest`, `testConcurrentDuplicateIssueBothSucceedWithOneMovement`. |
| R-008 | Unbuffered CSV streaming logic was about to be copied for a second report. | Extract method. | `iterateReportRows` held the buffered-mode toggle, cursor and cleanup inline. | Private `streamRows()` in `MySqlOperationalQueryRepository`, shared by order/ledger and outstanding exports. | `ReportQueriesIntegrationTest` (cursor released), `OutstandingReportIntegrationTest`. |
| R-009 | Outstanding report filters kept adding parameters to three repository methods. | Introduce parameter object. | `(scope, from, to, owner, document, bucket)` on every call. | `OutstandingCriteria` value object built and validated by `ReportService` (ADR-012). | `ReportPreviewTest` (scope per role, invalid filters rejected before query). |
| R-010 | Multi-item order lines would duplicate parsing and markup in PO and SO. | Extract class and shared partial. | Each controller built a single hard-coded item; each form had its own product fields. | `OrderItemsInput::purchase()` / `::sales()` and `views/partials/order-item.php` (clone template without field names). | `PurchaseOrderControllerTest`, `SalesOrderControllerTest`, business HTTP suite 76/76 (it caught the earlier named-template regression). |
| R-011 | A separate "Order" select duplicated header sorting and only sorted by date. | Replace control with shared header partials. | Direction select in PO/SO filters; arrows only on some columns. | `views/partials/sort-heading.php` (allow-listed key, arrow, `aria-sort`) and `sort-state.php` (keeps sort when filtering). | `ListSortingIntegrationTest`, UI sweep in `docs/testing/ui-ux-2026-10-07.md`. |
| R-012 | SonarQube reported unbraced control structures (php:S121, php:S2681) whose one-line style could mislead readers. | Automated, token-based formatting with PHP-CS-Fixer rule `control_structure_braces` (run once, not a project dependency). | `if (x) a; b;` style in 61 files. | Every conditional and loop body is braced; behaviour unchanged. | Full quality gate, business HTTP/browser suites and UI sweep after the change (`docs/testing/gap-closure-2026-10-07.md`). |
| R-013 | Verification scripts held literal database passwords and default TLS settings (python:S2068, python:S4423). | Replace literals with generated values; pin protocol. | Fixed disposable passwords in `scripts/verify-capacity.py` and `scripts/verify-operations.py`. | Per-run `secrets.token_urlsafe()` credentials and `minimum_version = TLSv1_2`. | `tests/Operations` 35/35; SonarQube vulnerabilities from 9 to 0 open (one reviewed and accepted, see `docs/quality/sonarqube.md`). |
